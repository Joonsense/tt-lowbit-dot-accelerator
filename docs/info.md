## How it works

A weight-stationary signed INT4 dot product accelerator. With `uio[6]` (LOAD) = 1, 8 bytes load the 16-element weight vector into the chip (two 4-bit values per byte, low nibble first). Then each x vector is 2 bytes with LOAD = 0, one byte per clock: the dot product with the stored weights is 8 MAC per clock. Weights stay until the next load, so many x vectors (a batch) reuse them. CHAIN (`uio[3]`) at the last byte of a vector carries the 20-bit sum into the next vector; the 16-bit saturate is applied once at the end. The MAC is pipelined (operand register, product register, accumulate, saturate). Activations are unsigned 1-bit values (0 to 1), 8 per byte, first element in the lowest bits. A 2-entry result queue lets the next vector stream in while results are read out; the chip holds back only the last byte of a vector, and only when every queue slot is taken, so no result is lost however slowly the host reads.

Design `6a45cc53-59a6-40f0-9fd6-7a438bf125e4` was verified in chip-lab against a fixed reference model and an RTL scoreboard, then wrapped for the Tiny Tapeout pinout.
Pre-layout sky130 standard cell area is 8297 um^2 and the selected tile size is 1x1 (estimate).

## How to test

Hold `uio[0]` (IN_VALID) with the byte on `ui_in`; it is taken on a rising edge where `uio[4]` (IN_READY) is 1. `uio[6]` = 1 marks weight bytes. After each 2 x bytes the 2-byte result appears on `uo_out`, least significant byte first, with `uio[5]` (OUT_VALID); `uio[2]` (OUT_READY) advances it. Back to back, one vector completes every 2 clocks. `uio[1]` (ABORT) discards a partial vector and sets `uio[7]` (ERR).

`host/pin_client.py` (MicroPython, demo board) has `load(w)`, `batch(xs)` and `batch_dot(w, xs)` for vectors of any length (weights loaded in chunks, partial sums added on the host). The cocotb tests run the same driver against the RTL.
